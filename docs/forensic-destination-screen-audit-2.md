## H. Exact root cause

The checked-out repository is internally consistent and correct: **new source, Metro resolves it, no duplicates, no nested projects.** The old UI seen on the device cannot come from any build of this tree:

- **Debug builds never read the checked-in bundle.** RN 0.86 Gradle plugin registers the bundle task only for non-debuggable variants (`node_modules/@react-native/gradle-plugin/.../TaskConfiguration.kt:65`). Debug loads JS at runtime from a Metro dev server whose IP/port is baked into the APK at build time (`AgpConfiguratorUtils.kt:90-112`, default port 8081).
- **Release builds regenerate the bundle from current source** into `build/generated/assets/react/release/` (`TaskConfiguration.kt:29-90`). This plugin version has **no** "reuse the checked-in bundle" fallback.

Therefore the installed app is running an APK (or a Metro server) produced from the **old source tree on the VICTUS machine** — the exact path embedded in the stale bundle. The old/new coexistence in git (old bundle + new source at HEAD) is real but **inert**: Gradle never selects the committed bundle.

**Case verdict:**
- CASE 1 (duplicate old source, Metro resolves wrong) → **disproved**
- CASE 2 (single correct source, stale generated bundle) → **yes** (the committed artifact is stale)
- CASE 3 (another RN project being built) → **disproved**
- CASE 4 (git has both old and new artifacts, Gradle picks wrong) → **partial** — both exist in git at HEAD, but Gradle cannot select the bundle
- CASE 5 (something else) → **the observed old UI comes from the VICTUS-machine build, outside this repo**

## I. Safest fix (diagnosis only — nothing executed)

1. **Rebuild + reinstall from this machine's repo.** `npx react-native start` then `npx react-native run-android`; if reusing the existing device, run `adb reverse tcp:8081 tcp:8081` so the debug APK reaches *this* machine's Metro. The stale APK has the VICTUS build's dev-server IP baked in. This alone yields the new UI.
2. **`git rm mobile/android/app/src/main/assets/index.android.bundle`** — dead, dev-mode artifact; RN 0.86 never consumes it. Safe to remove, and it stops old code from ever being packaged by mistake.
3. **Optionally purge old source** still carrying `PRESET_DESTINATIONS` (`main`, `origin/radium/ui`) so the old screen cannot be re-merged later.
4. **Set a real `GOOGLE_MAPS_API_KEY`** — currently the placeholder `YOUR_GOOGLE_MAPS_API_KEY_HERE` is injected from `gradle.properties`/`local.properties` into the manifest, and the source's API-key guard (lines 83/113/147) silently disables maps/Places. Without a real key, the new screen will render a blank map even after the rebuild.

No cache clears, Metro config changes, or source edits are required — this was never a resolution problem in the repository.
